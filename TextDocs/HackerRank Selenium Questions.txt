## Tier 1: Basic Level — Dynamic UI Validation & State Checking## Problem Statement
An automation engine loads a web page with a dynamic registration structure. Complete a method validateAndSubmitForm that performs the following sequential actions:

   1. Navigate to the target url.
   2. Locate the checkbox element with the ID terms-and-conditions.
   3. Check if the element is currently selected. If it is not selected, click it to check it.
   4. Locate the input text box with the attribute name='user-email'. Clear any pre-filled placeholder text and type the provided email string.
   5. Click the submission button containing the class btn-submit-form.
   6. Use an explicit wait to wait for a text alert banner with the class status-banner to appear. Return the String text value contained within this banner.

## Java Solution

import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.openqa.selenium.support.ui.WebDriverWait;
import java.time.Duration;
public class BasicFormAutomation {
    public static String validateAndSubmitForm(WebDriver driver, String url, String email) {
        // 1. Navigate to target URL
        driver.get(url);
        
        // 2. Check and select terms checkbox if unselected
        WebElement checkbox = driver.findElement(By.id("terms-and-conditions"));
        if (!checkbox.isSelected()) {
            checkbox.click();
        }
        
        // 3. Handle input field safely by clearing pre-filled text
        WebElement emailInput = driver.findElement(By.name("user-email"));
        emailInput.clear();
        emailInput.sendKeys(email);
        
        // 4. Click the submission trigger
        WebElement submitBtn = driver.findElement(By.className("btn-submit-form"));
        submitBtn.click();
        
        // 5. Handle headless server delays via Explicit Wait
        WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
        WebElement banner = wait.until(
            ExpectedConditions.visibilityOfElementLocated(By.className("status-banner"))
        );
        
        // 6. Return the raw string output
        return banner.getText();
    }
}

## Tier 2: Intermediate Level — Dynamic Tables & StaleElement Exceptions## Problem Statement
HackerRank frequently tests the ability to navigate changing DOM elements. Implement a method calculateTotalStock that sums up the stock count of products matching a specific text criteria:

   1. Navigate to the url.
   2. The page lists a table with the ID inventory-table. Each row is structured as a <tr> containing three cells (<td>): Name, Category, and Stock Level.
   3. Your method must scan through all rows on the first page.
   4. Identify rows where the text content of the Category cell matches targetCategory exactly.
   5. Extract the integer count from the Stock Level cell for matching items and maintain a running total.
   6. Exception Handling Requirement: The table updates its structure asynchronously every few seconds. If a StaleElementReferenceException occurs while scraping a row, recover gracefully by re-finding the table rows and continuing the count without crashing.

## Java Solution

import org.openqa.selenium.By;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebElement;import org.openqa.selenium.StaleElementReferenceException;import java.util.List;
public class InventoryScanner {
    public static int calculateTotalStock(WebDriver driver, String url, String targetCategory) {
        driver.get(url);
        int totalStock = 0;
        int maxAttempts = 3;
        
        // Define row locator globally to reuse for dynamic recovery
        By rowLocator = By.xpath("//table[@id='inventory-table']/tbody/tr");
        
        // Initial fetch of the rows list
        List<WebElement> rows = driver.findElements(rowLocator);
        
        for (int i = 0; i < rows.size(); i++) {
            int attempts = 0;
            while (attempts < maxAttempts) {
                try {
                    // Re-fetch the row list dynamically to avoid stale elements during loop iteration
                    rows = driver.findElements(rowLocator);
                    WebElement currentRow = rows.get(i);
                    
                    // Locate cell elements relative to the current row execution context
                    WebElement categoryCell = currentRow.findElement(By.xpath("./td[2]"));
                    WebElement stockCell = currentRow.findElement(By.xpath("./td[3]"));
                    
                    if (categoryCell.getText().trim().equalsIgnoreCase(targetCategory)) {
                        int stockVal = Integer.parseInt(stockCell.getText().trim());
                        totalStock += stockVal;
                    }
                    break; // Action succeeded, break retry loop to move to the next item
                } catch (StaleElementReferenceException e) {
                    attempts++;
                    // Fallback cushion block to recover node link state before retrying
                    if (attempts >= maxAttempts) {
                        System.err.println("Failed to parse row index " + i + " due to volatile dynamic layout updates.");
                    }
                }
            }
        }
        return totalStock;
    }
}

## Tier 3: Advanced Level — Shadow DOM Traversal & Multiple Window Handling## Problem Statement
On modern web platforms, traditional element querying methods (driver.findElement) fail when interacting with encapsulated components like Shadow DOM root boundaries or multi-tab flows. Implement extractSecureToken to solve the following setup:

   1. Navigate to the initial landing dashboard at url.
   2. Locate a button with the text identifier "Launch Portal". Clicking this button triggers a script that opens a brand new browser tab / window.
   3. Your driver context must track and switch over to this newly created window handle securely.
   4. On this new window, the primary UI component is hidden deep within a custom web component wrapper with the ID secure-widget.
   5. Access this custom component's Shadow Root context via modern Selenium 4 native capabilities, navigate internally to find an input block with the CSS tag selector input#token-field, and pull its value attribute string.

## Java Solution

import org.openqa.selenium.By;import org.openqa.selenium.SearchContext;import org.openqa.selenium.WebDriver;import org.openqa.selenium.WebElement;import org.openqa.selenium.support.ui.ExpectedConditions;import org.openqa.selenium.support.ui.WebDriverWait;import java.time.Duration;import java.util.Set;
public class AdvancedPortalAutomation {
    public static string extractSecureToken(WebDriver driver, String url) {
        driver.get(url);
        String originalWindow = driver.getWindowHandle();

        // 1. Click external link to launch a secondary browser window process
        WebElement launchBtn = driver.findElement(By.xpath("//button[text()='Launch Portal']"));
        launchBtn.Click();

        // 2. Loop handles collection using WebDriverWait until the new window registration appears
        WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
        wait.until(ExpectedConditions.numberOfWindowsToBe(2));

        Set<String> allWindows = driver.getWindowHandles();
        for (String windowHandle : allWindows) {
            if (!windowHandle.equals(originalWindow)) {
                driver.switchTo().window(windowHandle);
                break;
            }
        }

        // 3. Locate the Shadow Host element node
        WebElement shadowHost = wait.until(
            ExpectedConditions.presenceOfElementLocated(By.id("secure-widget"))
        );

        // 4. Use native Selenium 4 getShadowRoot() method (Bypasses manual JS Injection)
        SearchContext shadowRoot = shadowHost.getShadowRoot();

        // 5. Query inside the isolated shadow layout boundary using CSS Selectors (XPath is forbidden inside Shadow DOM)
        WebElement tokenField = shadowRoot.findElement(By.cssSelector("input#token-field"));
        String secretTokenValue = tokenField.getAttribute("value");

        return secretTokenValue;
    }
}

public class BrokenLinks {
    public static void checkLinks(WebDriver driver) {

## 1. Handling Synchronization (Implicit vs. Explicit vs. Fluent Wait) [4] 

* Scenario: Elements load asynchronously via AJAX or API delays. HackerRank evaluation code strictly monitors test stability and timing failures. [1, 4] 
* Question: What is the difference and when do you use each? [4] 
* Answer:
* Implicit Wait: Globally tells the driver to poll the DOM for a set period before throwing NoSuchElementException. Avoid mixing this with explicit waits because it causes unpredictable timeouts.
   * WebDriverWait (Explicit Wait): Halts code execution until a specific expected condition (like element visibility or clickability) is met. Always prefer this for production frameworks.
   * FluentWait: An extension of Explicit Wait that permits modifying the polling frequency and defining specific exemptions to ignore (e.g., NoSuchElementException) during the wait sequence. [4, 5, 6]

In an XPath selector, ../ selects the parent of the current element.
It allows you to look "up" the HTML tree instead of down. Think of it exactly like navigating directories in a command line or file system, where .. means "go up one folder."
------------------------------
## Why Use ../? (The "Reverse" Lookup)
In CSS selectors, you can only move downward or sideways to find elements. XPath is unique because it allows you to look up to a parent or ancestor.
The most common use case in automation is finding a generic element (like an image or a layout wrapper) based on a highly unique piece of text inside it.
## Visualizing the Difference
Consider this HTML snippet of a product card:

<div class="product-card">
    <h3>Wireless Mouse</h3>
    <button class="btn-buy">Add to Cart</button>
</div>

If you need to click the "Add to Cart" button, but there are 20 identical buttons on the page, you can anchor your search to the unique text "Wireless Mouse" and climb up the tree using ../:

//h3[text()='Wireless Mouse']/../button[@class='btn-buy']

## How Selenium evaluates this step-by-step:

   1. //h3[text()='Wireless Mouse'] → Finds the specific heading element.
   2. /../ → Moves up one level to its parent, which is the <div class="product-card">.
   3. /button[@class='btn-buy'] → Moves down into that specific parent's button.

------------------------------
## Alternative: The parent:: Axis
In XPath, ../ is actually a shorthand shortcut for the parent::node() axis.

| Shorthand | Full XPath Syntax | What it does |
|---|---|---|
| ../ | parent::* | Goes up exactly one level to the immediate parent. |
| ancestor::div[1] | ancestor::div[1] | Goes up multiple levels to find the nearest <div> ancestor. |

Tip: If you need to jump up 3 or 4 levels (e.g., ../../../../), it is usually cleaner and less brittle to use ancestor::div[@class='container'] instead of chaining multiple ../ shortcuts.

There is no direct CSS selector equivalent for that exact XPath because CSS selectors cannot navigate backward or upward to a parent element. CSS can only look downward (descendants) or sideways (subsequent siblings).
However, you can achieve the same goal in modern automation by using new CSS features or standard Selenium strategies.
## Option 1: The Modern CSS Way (Using :has())
If your test framework and browser support modern CSS (standard in most modern evergreen browsers like Chrome, Firefox, and Edge), you can use the :has() relational pseudo-class.
Instead of starting at the text and going up, you target the parent container that contains the text, and then go down to the button:

div.product-card:has(h3):has(button.btn-buy)

(Note: CSS cannot natively match exact text content like text()='Wireless Mouse', so this relies on structural tracking or data attributes).
------------------------------
## Option 2: The Practical Selenium Strategy
Since CSS cannot look up elements by text content, automation engineers typically handle this scenario in one of three ways:
## 1. Stick with XPath (Best for Text Anchors)
If you absolutely must use the text "Wireless Mouse" as your anchor, keep using XPath. It is the best tool for text-based traversal. You can make it slightly cleaner by using ancestor:: or following-sibling:: instead of ../:

//div[h3='Wireless Mouse']/button[@class='btn-buy']

## 2. Leverage Data Attributes (Best Practice for CSS)
If you have control over the application code, ask your developers to add a unique data attribute to the button or the card. This eliminates the need for complex traversal entirely:

<button class="btn-buy" data-product="wireless-mouse">Add to Cart</button>

The CSS selector becomes incredibly simple:

button[data-product="wireless-mouse"]

## 3. Split the Logic in Selenium (Code-based solution)
If you prefer to avoid XPath completely, you can find the container first using standard Selenium methods or Playwright's text locators, and then scope a CSS selector inside it.

To use the following-sibling axis in XPath, you use the syntax following-sibling::tag_name.
This axis allows you to find elements that share the same parent and come after your current element in the HTML tree. It is highly useful because it allows you to look "sideways" without needing to climb up to the parent using ../ first.
------------------------------
## Visualizing the Syntax
Consider this HTML structure for a form or table row:

<div class="row">
    <label>Username</label>
    <input type="text" class="form-input">
    <span class="error-msg">Username is required</span>
</div>

## Example 1: Finding the Input field next to a specific Label
If you anchor your search to the text "Username", you can target the input box directly next to it:

//label[text()='Username']/following-sibling::input


* How it works: Selenium finds the <label>. From there, it looks forward among its brothers and sisters (siblings) to find the next <input>.

## Example 2: Finding the Error Message
If you want to grab the error message associated with that specific username field:

//label[text()='Username']/following-sibling::span[@class='error-msg']

------------------------------
## Key Rules to Remember

   1. They must share the exact same parent: following-sibling will not look inside neighboring divs or jump out of the current container.
   2. It only looks forward (downward in the HTML): It will only find elements that appear after your anchor element. If you need to find a sibling that comes before your anchor, use preceding-sibling:: instead.
   3. It matches all subsequent siblings by default: If there are three inputs after your label, following-sibling::input will find all three.

------------------------------
## How to handle multiple siblings (Indexing)
If you have a list where multiple matching siblings exist, you can use numbers (indices) to target a specific one. Note that XPath indexing is 1-based (not 0-based).

<p class="header">List of Items</p>
<li>Item A</li> <!-- Sibling #1 -->
<li>Item B</li> <!-- Sibling #2 -->
<li>Item C</li> <!-- Sibling #3 -->


* To get Item A (the very next sibling):
//p[@class='header']/following-sibling::li[1]
* To get Item B:
//p[@class='header']/following-sibling::li[2]

## Shortcut Alternative: following::
Be careful not to confuse following-sibling:: with following::.

* following-sibling:: strictly looks at elements sharing the same parent.
* following:: looks at every single element that comes after the anchor in the entire HTML document, regardless of structure. (Usually avoided because it is too broad and slow).
